# 角色模型配置

控制台左侧「模型设置」可分别设置主会话、工具助手、潜意识助手、话题助手的模型及推理强度。模型列表复用 DSH 已注册的提供方，不在此页面保存或展示凭证。

主会话与工具助手留空时跟随 DSH 默认；潜意识与话题助手留空时跟随主会话。任务详情中的独立模型优先于该类助手的配置，恢复跟随后不影响其他任务。潜意识 Fork 也会应用独立配置，不被父会话的旧模型锁住。

配置按角色持久化在现有 SQLite 中，重启保留。保存后从下一次模型请求的提示词组装阶段生效，当前请求及其重试维持原路由。不清空历史，不重建会话，不中断任务，不修改 DSH 全局默认。模型可用性和推理强度使用 DSH 原生校验；图片及工具能力取决于所选模型。

仅管理员可访问 `GET/POST /api/models`。GET 可带 `catalog=1` 获取可用模型，带 `task_id` 查看单任务配置。POST 使用 `{scope, selection}`，scope 为 main/worker/continuation/topic；selection 为 `{provider, model, reasoningEffort?}` 或 null。单任务配置另带 task_id，必须与角色及任务类型匹配。沿用控制台认证、同源检查与请求标记保护。提供方错误不直接回显，避免泄露凭证。

## Agent 切换后的 API 连通测试

Main 通过 `amphoreus_settings(section=models)` 预订任一角色或单任务模型切换时，工具仅返回「已预订」，立即结束。预订以原生调用编号去重，保存在现有 SQLite；后台独立发起「Reply OK.」短请求，最多输出 64 Token，API 请求 30 秒超时。不使用 Main/subagent 的运行槽，不带 Persona、会话历史或工具，不等待 Agent 继续执行，也不唤醒会话或发送平台消息。

测试通过后才原子提交路由与成功结果；配置校验失败、网络错误、空响应、错误结束或超时保留原配置，并记录「已回退」。更新同一目标时，过时预订不会覆盖较新的预订或管理员设置。清除任务覆盖会测试将继承的有效模型；中断的测试在重启后恢复，已完成的不会重测，提供方错误不原样回显。

完成结果在 Main 或受影响的已有分支下一次正常对话/激活开始时，以简短原生 notice 注入；本轮中途不插入通知，未完成时继续等待后台，下次有结果再告知。通知落盘后才确认已读，重复交付以稳定编号去重。Main 会收到所有预订结果；指定任务及预订时正在使用相应默认模型的分支也会在各自下一次激活收到结果。无需轮询。

测试消耗计入被设置角色的 Token 统计，日志标为「模型API连通测试」，不计为角色新激活。测试通过表示短请求可用，不保证所有图片、工具能力或后续网络始终正常。

## 切换不中断会话

模型切换只保存路由选择，不取消正在输出的请求、不重建 Agent/Session、不清空历史或重放工具。当前流式回复及其重试继续使用组装时的模型；新配置从后续步骤的下一次提示词组装开始生效。API 探测独立进行，失败回退也不取消当前请求。正在执行的工具照常完成，后续工具结果留在同一会话中供模型继续处理。

离线回归使用原生 Session 和路由事件，在流式请求尚未结束时分别验证控制台切换、Agent 探测成功和探测失败：旧流完整结束、当前请求路由不变、Session ID 与原有消息保持。此验证不向在线角色发送测试消息。
