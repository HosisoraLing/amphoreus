# 话题串、按需召回与可开关后台整理

话题不是只有摘要或另一个子会话。每个稳定 `topic_id` 下面维护有序、不可覆盖的 `topic_entry`：收到的对话原文（message）、角色实际发言（speech）和 Main 的想法／自言自语（thought）。每项保存原始文本、原始 memory ID、时间、发言者、平台／账号／会话和原生来源。摘要独立版本化，不替换原文；旧摘要保留。

这里的“想法”是原生归档里 Main 的 assistant 文本，不把它说成已经发言或行动。接口 reasoning 仍按已有 provider 白名单与保留期处理，不复制进永久话题串绕过策略。worker/topic 的工作日志不冒充角色 Main 的个人想法。

原文成员在现有 `amphoreus_memory` 表中作为独立 `kind=topic_entry` 保存；不增加恢复工具未知的新表。媒体只复制可定位的地址／附件 ID／转发或引用 ID，不复制图片 base64 或平台 transport 对象。实际媒体原件依旧通过原始归档读取。原始文本和来源不被模型的分类结果改写。

## 查询

`read_topic` 默认只返回摘要、条目总数等元信息，不附上原文、原文预览或全量来源清单。

```json
{"id":"稳定话题ID或摘要版本ID"}
{"id":"稳定话题ID","include_original":true,"offset":0,"limit":8}
{"id":"稳定话题ID","include_original":true,"offset":0,"limit":1,"text_offset":4000,"size":4000}
```

`offset/limit` 分页条目；`text_offset/size` 分页长条目的原文。返回 `next_offset` 和逐条 `next_text_offset`。默认8条，最多20条，每段正文最多12000字符；不能靠原始text block绕过正文分页。图片始终是引用。原文按原始时间排序、同一时间以归档插入次序稳定排序；消息、发言和想法明确区分。单条分配到同一话题的ID固定，重试不会重复。

摘要本身默认最多4000字符；超出会标记summary_truncated，可通过原有 memory_read 对摘要版本分页读取。

`topic_agent` 仍可按需询问持久话题助手，默认携带摘要；可传 `include_original=true,offset,limit` 显式带一页原文。它与自动整理Agent是两条独立链路。读取旧版本ID时返回当时摘要，但原文成员是整个稳定话题串的累积内容，不宣称重建某一版本时刻的原文快照。

管理员接口 `GET /api/topics` 列表；`GET /api/topics/:id` 摘要；加 `?include_original=true&offset=0&limit=8` 取原文。与既有全局记忆一样仅管理员可读，普通chat用户403。

## 自动整理

Main工具 `topic_organizer` 和管理员 `GET/POST /api/topic-organizer`、控制台“记忆与自我”里的“话题串与后台整理”共用持久设置。

```json
{}
{"enabled":true,"intervalMs":60000,"batchSize":12}
{"enabled":false}
```

默认关闭。开启后以启用时的数据库位置为水位，只处理之后新增的合格原文、已发送发言和Main想法。关闭期间的记录不自动重放；重新开启从新水位开始。没有擅自做历史全量回溯或花费历史Token。

默认每60秒检查一批，最多12项；间隔范围10秒至1小时，每批1至30项。空闲时检查数据库但不请求模型；同一时间仅一批分类。当前使用配置的worker模型，缺失时用Main模型；若均未配置，报错而非偷偷使用全局模型。

每批只调用一次模型，输入有边界（每条文本前2500字符、最近40个活跃话题摘要前600字符、媒体引用，输出最多4096 Token）。这是独立无工具分类 Agent，没有Main整段聊天上下文、QQ发言、Shell或Self写入权限。当前候选为最近40个活跃话题：极久未活动且不在候选里的话题可能被新建为相近话题；不是全库无限制语义聚类，也不是零成本运行。完整原文仍完整保存，只是分类输入有截断上限。

模型输出按组选择已有topic_id或新话题new_key，每个输入ID必须且只能出现一次。程序验证ID、话题范围、二选一、重复和遗漏后，在单事务内提交摘要版本、原文成员与完成标记。分类输入是资料不是系统指令；程序不执行模型提出的任意工具或外部动作。

若期间已有话题被别的任务更新，乐观版本检查阻止覆盖新摘要，下一次重试刷新候选。每批和原文分配持久化，进程恢复可重试，无半份提交。分类或请求失败最多3次后自动关闭，界面展示失败原因，避免无限烧Token。关闭/停服务会取消未提交模型流，不保证追回已经发生的Token消费。

黑名单／接收策略在选批和提交前复核。整理模式还遵守角色总开关：角色关闭时不发起推理，并取消未提交分类；渠道和会话关闭的来源也不入选。后台不唤醒Main，不发送QQ消息。既有历史已进入摘要或Main脑海的知识不因此删除。已有话题的有效原始source_ids会迁入话题成员（幂等），保留旧摘要和原文。

## 验证边界

自动化测试使用临时数据库、模拟分类和模型流。运行验收应按实际宿主、模型与传输渠道另行验证；不会为了测试默认发送真实消息。部署时保留已有配置、记忆和会话历史。
