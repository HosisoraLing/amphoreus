# 人际关系插件迁移

沿用原 `@local/dsh-people` 的 SQLite 表、人物 ID、稳定账号、印象、依据、邮箱与审计记录。运行库存放在当前角色实例状态目录的 `people.sqlite`。首次启用时，从 **当前实例自己的** `amphoreus/legacy-fishtank/.consistent/home/people/people.sqlite` 独立复制；不挂载旧鱼缸，不覆盖已有运行库，后续修改不影响迁移归档。

旧插件把缺少原频道身份的会话当作 Harness 管理员；现在改为读取统一网关的可信来源。QQ 以 QQ 号认人，Web 以配置账号命名空间认人，昵称只用于查找。仅 `people.ownerIdentities` 中的明确账号及管理端拥有者可以关联身份；不会按相同昵称或聊天中的自称自动合并。配置示例：`{"people":{"ownerIdentities":["qq:12345678"]}}`。

Main 使用 `people_get`、`people_list`、`people_note`、`people_contact`、`people_link`；工具助手、潜意识及话题 Agent 只获得前两个查询工具。写入带网关来源、原消息标识、会话和依据；账号关联保留审计，关联后的人物资料包含双方印象与邮箱。跨平台经历仍可由同一角色回忆，印象的 public/private 只是来源标签，不能据此擅自向其他用户公开资料。

当前来信仅注入该人物的两条短印象，更多关系按需查询，不把完整人物库放进每轮提示词。所有原始来信仍按现有规则归档，人物库不会替代全局记忆。后台按游标登记稳定账号，昵称和 last_seen 使用原插件的粗粒度更新以减少写盘。

原侧栏管理页和独立控制台均增加「人际关系」：分页查找、登记账号、维护印象与依据、邮箱、拥有者确认的关联/拆分。`/api/people` 的读写均仅限管理员，沿用已有认证、同源写入检查和 Host 校验，普通聊天账号无权浏览完整关系库。页面使用文本节点显示资料。

角色当前暂停时，只执行迁移和离线检查，不为验证启动 Main、NapCat 或模型请求。恢复运行后新工具及页面才生效。
