# QQ 群聊参与

在 Harness 左侧栏进入翁法罗斯，打开「群聊参与」。配置保存在现有 SQLite 中，保存后立即生效，重启保留。

- **心意模式**：已启用群的每条消息都交给同一个 Main，由角色决定是否调用 `speak`，不经过概率、冷却或精力门控。
- **混合调度**：普通消息先合批，再由 Runtime 判断是否值得唤醒。明确 @、回复她的消息、角色明确等待的一次回答优先进入 Main。
- 开启 QQ 消抖时，群消息先合并，再交给同一个参与调度器；消抖批次不会直接唤醒 Main。混合模式的概率、冷却、精力等规则继续生效；心意模式保留消抖效果，一个批次只交给 Main 一次。批次内的明确互动仍按直接互动处理，回复来源指向那条真实来信，原文顺序保留。私聊消抖不经过群聊参与概率。
- 两种模式都保存全部原始消息；图片、动图、语音、视频、文件和合并转发都计作消息。消息不需要附带文字。
- 图片及动图按原顺序进入原生视觉上下文；语音由已配置的 MiMo 转写；文件仅显示文件名，视频仅显示封面，合并转发默认显示 QQ 风格预览。
- 普通 `assistant.content` 继续作为想法归档；只有 `speak` 发言。Main 可以观察后保持沉默。

原群会话、账号、消息、发送者、时间及引用均保留，观察事件使用 `qq-observation` 来源并引用原始 `napcat` 事件，输出仍走原 QQ 会话。不会将 QQ 入站转换为 Web 用户来信。

## 上下文与实际观察

Heart 依靠 Main 连续 Session、Persona、Self 和当前真实来信，不自动查询或注入跨渠道近期快照、人物印象、全局记忆或话题摘要。可以主动使用现有记忆和人物工具；只附带已有 `topic_entry` 能验证的 TID，不为生成 TID 调用模型。明确的消抖/观察批次仍按真实消息顺序入模。

Hybrid 在当前群聊、当前账号内补足未观察区间。优先使用来源完全位于该区间的已有话题摘要，否则提供有界原文摘录及媒体类型标记；不在实时路径等待新的模型调用，也不改变参与概率公式。`memory.socialContext.hybridBudgetTokens` 默认 1000，使用宿主 Token 估算器；缺少估算器时以 UTF-8 字节数保守计量。`memory.socialContext.enabled=false` 可单独关闭附加上下文。

真实来信只有在原生 `user/message` 入栈时确认；系统段里的遗漏内容只有在对应 `request/header` 提交后才确认。计划、逐条观察标记和来源游标持久化，游标之前尚未展示的空洞仍可补入。消息落库、概率门处理或准备摘要不会推进观察状态。Steering 采用相同路径；已入栈批次及已经观察的 Heart 消息不会在切回 Hybrid 时重复总结。内部回顾、后台报告、Web 指令不套用 QQ 群聊策略。

## 混合调度默认值

| 项目 | 默认值 |
| --- | --- |
| 模式 | 混合调度，已有持久化选择优先 |
| 基础概率 | 迁移现有 `qq.activeReply.probability`，独立设置默认 5% |
| 观察窗口 | 60 秒，可配置至 120 秒 |
| 每批消息 / 文字预算 | 20 条 / 12000 字符 |
| 批次概率 | `min(.25, 1-(1-p)^min(n,5))` |
| 主动冷却 | 12 分钟，成功发送后开始；静默、失败与未知结果不开始 |
| 参与惯性 | 120 秒；普通聊天不会自动续期 |
| 发言统计 | 最近 10 分钟内最多 20 条真实消息，成功发送才计入 |
| 占比调节 | 20% 降低，35% 显著降低，50% 暂停普通唤醒 |
| 精力调节 | 40% 降低，65% 显著降低，80% 暂停普通唤醒 |

已有启用群保留设置，新群默认只归档及处理直接互动，不自动启用随机插话。可以单独设置每群的模式、启用状态、概率、合批窗口、消息上限、冷却、惯性及占比阈值。

混合模式在 Main 忙碌时，每群最多保留一个已排队观察及一个有界缓冲；更多原文仍在 Event Store 中。直接互动优先于普通观察，替换尚未执行的重叠观察。幂等批次、源游标、随机决定、发送回执及冷却均持久化。

## 精力与话题接口

`main-vitality` 记录保存最新 Main 使用量、真实模型窗口、输出余量及共享睡眠标记。使用量包括未缓存、缓存读写及输出 Token；有效容量取 `min(750000, contextWindow-outputReserve)`。没有使用量时管理页面显示「接口未提供」，不声称已测得精力。

`captureVitality` 从原生 Session 的请求元数据和 usage 更新使用量。既有或后续睡眠调度可设置 `sleeping` 或 `phase=awake/drowsy/resting`。这里不实现另一套睡眠人格或自动切换清醒周期；目前夜间回顾不等同于正式睡眠。90% 的强制休息仍由睡眠调度负责。

Main 可用 `group_participation` 标记实际参与的话题、明确等待的一位群友或退出。仅同 Topic 元数据匹配时增加普通参与机会；不会把所有连续群消息当成同一话题。等待回答只豁免一次，超时失效。其他机器人可用群设置的 `botIds` 排除，结构化 `sender.is_bot` 也会被识别，不通过昵称猜测。

## 管理接口

`GET /api/participation` 获取配置、各群状态、因子及短日志。管理员使用 `POST /api/participation`，请求体为 `{ "settings": { "mode": "heart" } }`；指定群时额外提供 `group`。沿用 Harness 登录及写请求保护，聊天用户无权读取或修改。

消息中心明确区分「等待观察」「本批未唤醒」与「已送达角色」。参与日志不复制消息全文。

## 验证边界

自动化覆盖普通消息合批、纯图片、五种无文字附件、心意模式、静默不冷却、实际成功发言、@ 与引用、睡眠/精力/占比抑制、重启不重抽、有界排队和直接交互优先，以及 UI 模式保存和管理权限。

模拟测试不等于真人群聊行为验收。生产保持管理员选择的心意模式；混合模式的真实群聊频率需由管理员试运行后调校。
