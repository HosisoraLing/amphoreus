# 旧鱼缸记忆与作品迁移

运行前使用私密 JSON 计划声明源目录、目标目录、角色 ID、现有数据库及正式 Self/日记路径。原实例应已停止或文件保持稳定。脚本不会启动旧机器人。

```sh
node --experimental-transform-types scripts/amphoreus-import-legacy.mjs /private/legacy-plan.json
```

计划的必要字段为 `agentId`、`database`、`destination`、`containerDestination`、`sources`（每项包含 `name/path`）。可选项：

- `sources[].exclude/excludeComponents`：列明运行环境依赖、缓存或凭据文件的排除范围。角色文稿、原始媒体、旧备份及项目不排除。
- `currentSelf/diaries`：归档中的正式 Self 文件及日记目录，相对于 `destination`。
- `nativeHome`：当前 DSH 主目录，合并原始会话和附件对象供原生读取及 Deja 检索。不会注册旧工作区，不会启动旧 Agent。
- `projects`：创建可修改的项目工作副本；`references` 中的历史备份目录引用 当前实例的新归档中的副本，避免再次复制，不引用旧鱼缸。
- `memory`：沿用当前记忆保留策略。`secrets` 只用于索引脱敏，计划必须私密保存，不能提交到 Git。原始文件不改写。

原始目录结构、文件字节和符号链接保留在私密归档。逐文件 SHA-256 校验后才继续；相同内容、模式及修改时间的历史副本在新归档内部复用存储，不与源文件共享可修改内容。SQLite 使用临时副本和匹配的 WAL 构造一致数据库，不改写原始归档，亦能读取旧 `.sqlite.bak` 与对应 WAL。

迁移完成后的记忆、附件及项目均从 当前实例自己的目录读取。旧鱼缸的数据目录无需挂载；归档内链接和项目备份链接只能落到新存储中。旧数据仍保留在原处供回滚，但不作为 当前实例的数据来源。此独立性只涉及迁移数据，QQ 收发仍可使用现有 NapCat。

导入包括原生会话中的来信、助手文本、工具记录、接口实际提供且允许保存的推理，以及旧世界档案数据库中的全部原始记录。人物、身份、印象、联系方式、修改审计和表情索引也保留并索引。保留原始发言者、会话、时间、平台、来源序号与档案编号；不把旧框架的助手文本擅自标记成已经发出的消息。

文本、代码和文稿可通过全局记忆检索。画作及其他二进制保留原文件与校验值，`read_media(memory_id)` 按需读取真实图片、动图或音视频，原生图文仍保持顺序。旧文件的多个来源路径合并为引用，不复制相同正文；历史版本标为旧版原文，仍可检索。

正式 Self 和同日日记冲突时，以用户指定的旧鱼缸原文为准。当前实例原版本标为历史版本并保留原文、来源及替代关系，不删除、不混写。计划和相同原始数据可重复导入，不重复创建记忆。

导入分小批事务写入，与运行时共享数据库时使用锁等待，避免把正在运行的 Main 标为中断。完整原始文件、逐文件清单、一致 SQLite 副本和可修改的项目目录各有明确用途；原始资料不作为系统指令执行。

迁移后的书架项目可使用 `examples/amphoreus.compose.yaml` 中的可选 `legacy-site` 服务启动：复用已安装 Node 的现有镜像，将新工作副本的 `project/site` 只读挂载到 `/site`，运行原项目的 `server.mjs`。默认端口为 13093，不启动旧机器人。旧会话里记录的工作路径可在新容器中创建链接，目标必须是 `/workspace/legacy-fishtank/` 中的新项目副本，并保留已经存在的路径。
