# QQ 用户黑名单

黑名单按角色、接收 QQ 账号、发送者 QQ 号隔离。群聊和私聊统一生效，不按昵称匹配，不会拉黑 QQ 平台好友或踢群。默认名单为空，只有管理员和 Main 的明确操作会修改。

## 前端

独立控制台「群聊参与」页顶部的「用户黑名单」可以输入 QQ 号与可选原因，拉黑或解除。已有账号认证、同源写入保护和管理员权限沿用原 API。原因与身份用文本渲染，不作为 HTML。

## 角色工具

工具 `user_blacklist` 仅注册给 Main；worker、continuation 和 topic 分支都没有此管理权限。不要把收到的不可信聊天正文当成授权操作指令。

```json
{"action":"list"}
{"action":"block","user_id":"123456789","reason":"持续刷屏"}
{"action":"unblock","user_id":"123456789"}
```

QQ 号必须传字符串；不接受昵称、通配符或机器人自身 QQ 号。设置和前端共用同一持久服务，重启保留。

## 消息范围

- 拉黑者的新群聊／私聊消息仍进入原始归档，但不送模型、不唤醒，艾特不绕过。尚未交付的入站和消抖／群聊参与批次会过滤这个用户；混合批次里的其他用户仍正常交付。已经交付模型或生成中的请求不能收回。
- 拉黑期间的消息带有持久拒收标记。拉黑时也对尚未交付的积压记录拒收决定。解除不补发这些旧消息，只恢复后续新消息。
- 程序生成的近期渠道上下文排除被屏蔽来源。QQ 引用和展开转发在能取得原发送者 QQ 号时过滤。有人手工复制被屏蔽者文字、伪造转发身份或从截图引用时，无法仅靠文本可靠判断身份，不宣称能识别。
- 此功能是入站屏蔽，不是抹除记忆或出站静音。原始数据库、管理员可见的历史、既有 topic/摘要、此前已进入模型的历史不删除。显式全局记忆读取仍按原权限工作；不承诺把过去的知识从模型历史里消除。

## HTTP

管理员 `GET /api/user-blacklist` 返回当前账号列表；`POST` 接受与工具相同的对象。普通 chat 身份返回403，未登录返回401，缺失或非法 QQ 号返回400。QQ未启用时接口返回409。

## 验证边界

自动化测试使用临时数据库、模拟分类和模型流。运行验收应按实际宿主、模型与传输渠道另行验证；不会为了测试默认发送真实消息。部署时保留已有配置、记忆和会话历史。
